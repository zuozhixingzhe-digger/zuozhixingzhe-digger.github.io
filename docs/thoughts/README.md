## 一、怎么读原稿

原稿 5 张，画的是同一件事的三个层次：

```
original/window.svg          original/red.svg
┌────────────────────┐       ┌──────────────┐
│  ● ●   ╱‾‾╲   ● ● │        │  ┌─────┐     │
│       ╱ title ╲    │        │  │  ╲   │    │   ← 红：右侧开口的框 + 一支甩出的月牙
│ ┌────────────────┐ │        │  └──╲──┘     │
│ │    content     │ │        └──────────────┘
│ └────────────────┘ │
└────────────────────┘        original/green.svg
                               ┌──────────────┐
画面 160.151 × 110.589         │  ╲        ╱  │   ← 绿：四角星，四条边向内凹
提手 底69.164 / 顶42.535 / 高16.089  │   ╲    ╱   │
色点 ⌀10，cy≈72.2              │    ╲  ╱    │
                               └──────────────┘
```

三条贯穿全部，原稿自己就立住了，不需要另加：

1. **标题零布局影响** —— 提手和色点在画面之外/之上，画面永远是完整的 160.151 × 110.589。
2. **提手是提手，不是标题栏** —— 它有自己的宽度（底 69.164），标题塞不下就截断，不许把它撑大。
3. **只有画面是实体** —— 除画面外全部透明，提手是玻璃，色点是实心。

几何与原稿的对应关系（单位 mm，**和原稿完全一致**）：

| 项 | 原稿 | 修订版 | 说明 |
| --- | --- | --- | --- |
| 画面 | `rect1` 29.219, 80.260, 160.151 × 110.589 | 同 | 一个数没动 |
| 提手 | `path1` 73.973→88.027→130.562→143.137 | 同 | 只把两只脚的 y 收到 80.260 |
| 色点 | `ellipse` ×4，cy 71.5~72.8 | `circle` r=5.0，cy 72.216 | 椭圆改正圆，位置镜像 |
| 色点间距 | −48.3 / −36.0 / +38.2 / +53.6 | ±50.9 / ±37.1 | 取两侧平均，不另设数值 |
| 标题 | x 97.682, y 77.283, 12.7units | 居中 109.295, y 77.35, 4.2units | 字号按成品改 |
| 画布 | 210 × 297mm | viewBox `24 57 170 145` | 只切白边，图形不动 |

**缩放**：`width=680 height=580`，viewBox 170 宽 → 4 倍。所以文件里任何数值 ×4 就是屏幕像素。
一个 640px 宽的窗口，色点直径是 40px，提手高 64px —— 都是原稿比例算出来的，不是我挑的。

## 二、改了什么（逐条）

只有 8 条。每一条都能在原稿和修订版之间对着看。

### window.svg

| # | 原稿 | 修订 | 为什么 |
| --- | --- | --- | --- |
| 1 | A4 画布（210×297mm），内容缩在中间一小块 | viewBox `24 57 170 145` | 画布不是设计。切掉白边，图形一个像素没动 |
| 2 | 提手两只脚的 y = 79.890 / 79.150，画面顶边 y = 80.260 | 两端都收到 80.260 | 原稿的脚悬空了 0.4~1.1mm。放在深底上会看到提手没落地 |
| 3 | 提手顶边两端 y = 64.356 / 63.986 | 统一 64.171 | 原稿顶边左右差 0.37mm，横杆是歪的 |
| 4 | 四枚 `ellipse`，rx/ry 5.03/4.71、4.77/4.51、5.49/4.97、5.17/5.10 | `circle` r = 5.0 | 原稿的四点是扁的、大小不一。压成椭圆是手抖，不是设计 |
| 5 | 四点偏移 −48.3 / −36.0 / +38.2 / +53.6（左右差 5mm） | ±50.9 / ±37.1 | 同一个原因。取两侧平均，保住"内两点贴提手两脚、外两点再外一档" |
| 6 | 白描边 + 黑字（画在白纸上） | 深底 + 浅字 + 1px 细轮廓 | 这是**唯一一处不是"改错"的改动**：原稿是设计稿的画法。深色终端必须反极性 |
| 7 | 画面是直角矩形 | `rx=3`（12px） | 同上。你要求"模仿 macOS"，macOS 的窗口是圆的。这条是我补的，原稿没有 |
| 8 | `rect1` + `path1` 两条独立路径 | 合成一条闭合轮廓 | rect 的顶边会横穿提手根部，画出第二条线。合并不改变线的走法 |

### window-fullscreen.svg

原稿没有全屏图。这一张是按你定的规则推的：**普通态靠透明藏起来的地方，全屏时一律换成毛玻璃**。

普通态有两处透明：提手本身，以及提手两只脚与画面顶边之间的两个阴角。
全屏时没有桌面可露，**这两块一起填成一条 16.089mm 高的毛玻璃带**，画面顶边因此变平。

- 几何全部沿用主图：带子 y 64.171~80.260，色点 cy 72.216，标题基线 77.35。
- 变的只有画面顶边：从 80.260 上移到 64.171。
- 提手轮廓留在带子里，作为一道极淡的凸起，位置还在，边界已经不属于画面。

（上一版我把提手翻进画面做成"向下梯形凹槽"，那是我自己发明的东西，你原稿里没有，已删。）

### 四枚按钮

| | 形状来自原稿 | 只动了什么 |
| --- | --- | --- |
| 红 | `rect12/13/14` 三条边围成右侧开口的框 + `path14` 一支从框内向右下甩出的月牙 | 三条矩形的底边对不齐（198.247 / 197.876），合并成一条闭合路径对齐；`path14` 中间那段 `-9.246,138.699 0,-0.370 0,-0.370 0,0` 是拖节点留下的残迹，控制点飞到 y=340（画布外），删掉 |
| 黄 | `path1` 一块折角：上边平、右边直，底边一条长弧兜回左上 | **路径一个数没改**，这条本来就是干净的 |
| 绿 | `path1` 四角星：四个尖角撑在四角，四条边向内凹 | 原稿路径里夹着三段 `0.370,-0.370` 退化段，整条甩出画布（x 到 −11.3/+225.4）。沿原稿**实际渲染出来的轮廓**量了 4 个尖角 + 4 个内凹深度，每条边用一段圆弧接回去 |
| 蓝 | `rect1` + `rect2` 两片咬合的方形，靠十字缝讲遮挡 | 原稿的缝只有 0.37mm，缩到 26px 是 **0.045px**，必然消失。缝重新给到 0.8，两块的形状与咬合关系不变 |

四枚共同的改动只有一条：**白描边去掉，填充换深墨 `rgba(0,0,0,.58)`**。
原稿的 `stroke:#fff` 是"画在白纸上才看得见"的产物；落到彩色圆点上，它就是一圈噪点，而且黄底上的白等于没有。

缩放：原稿 bbox 按高度归一到 26px，居中放进 ⌀40 的圆点。

> **绿的那条要说清楚**：这是四张里唯一重写了路径数据的。原稿的 path 坏了（丢了几段、控制点飞出画布），
> 无法"只改数字"地救回来。我量的是**原稿渲染出来的轮廓**，所以形状还是你画的星形，不是我另画的。

## 三、两条容易被做错的规则

### 1. 标题塞不下：中间截断，提手不许变宽

```
hsl2 · FreeBSD 12.0-RELEASE r341666 · 第 1 层     ← 完整，45 字符 ≈ 94mm
hsl2 · FreeBSD 12.0…第 1 层                        ← 截断，56mm
```

保留**头**（身份）和**尾**（状态），砍中间。`text-overflow: ellipsis` 只能砍尾，所以要量宽：
以**标题基线处提手的宽度**为准（原本 2×32.17 = 64.3mm，留 4mm 呼吸 → 60mm 可用）。

`window-fullscreen.svg` 用的就是截断后的那一行。

### 2. 全屏：缺口变毛玻璃

| 普通态 | 全屏态 |
| --- | --- |
| 提手抬在画面**外面** | 提手沉进画面，被毛玻璃带接住 |
| 提手两脚与画面顶边之间是两个**阴角** | 阴角填平，画面顶边变成一条直线 |
| 缺口 = 透明 | 缺口 = 雾层 + 细颗粒 + 一道厚度高光 |

落地用 `backdrop-filter: blur()` + 半透明白 + 一层噪点，不必真的画图。

## 四、落地参数（640px 窗口）

| 项 | 值 | 来源 |
| --- | --- | --- |
| 画面 | 640 × 442，圆角 12 | 160.151 × 110.589mm ×4 |
| 提手 | 实体，填画面色，不是半透明玻璃 | 见下 |
| 提手 | 底 277 / 顶 170 / 高 64 | 69.164 / 42.535 / 16.089 ×4 |
| 提手顶角半径 | 6 | 原稿顶角是尖的，加一点圆角，别太锐 |
| 色点 | ⌀40，cy 距画面顶 −32.2 | ⌀10，8.044mm ×4 |
| 色点偏移 | ±148.4（内）/ ±203.6（外） | 37.1 / 50.9 ×4 |
| 标题 | 16.8px / 500，基线距画面顶 11.6 | 4.2mm，2.91mm ×4 |
| 轮廓 | 1px `rgba(255,255,255,.13)` | — |
| 投影 | `0 18px 22px rgba(0,0,0,.55)` | — |

> **提手是实体，不是玻璃。** 这是这次返工最大的一处修正。
> 一开始我把它填成半透明玻璃（"只有画面是实体"那句的直译），结果提手根部与画面差一个色阶，
> 看过去像两块板中间夹了一条缝 —— 数据上确实差 15 个亮度级。原稿那圈线框描的不是"一片玻璃"，
> 而是"画面向上凸出的一块"，所以填画面色、顶部略受光，才和画面连成同一条轮廓。

落地结构：

- 画面 `inset:0` 铺满；**提手与色点是 `position:absolute` 的兄弟节点，不进文档流**。
- 拖动热区 = 顶部整条 64px（提手 + 两肩空白），双击 = 最大化 / 还原。
- 四枚色点用 `<button>`，`aria-label` 写「关闭 / 最小化 / 最大化 / 置于底层」。
- 全屏切换的是**同一套 DOM**，只加 `is-full` 类。

## 五、还没定的一件事

**色点直径 = 画面宽的 6.25%，是 macOS 的 4 倍。**

原稿里点画 10mm，是因为 A4 纸上笔能画的最小圆差不多就这么大 —— 这可能是手绘的下限，不是设计意图。
按原稿做，640px 窗口上就是 ⌀40，四个点加起来占窗口宽度的 61%，很重。
缩到 macOS 比例（⌀24）看着顺眼，但 26px 的图形缩进 15.6px 就什么都认不出了。

两条路，等你定：

- **A 保持原稿**：⌀40，图形看得见，窗口显壮。
- **B 缩到 ⌀24**：接近 macOS，但四个图形必须为小尺寸重画一版（就不是原稿的形状了）。

`hterminal-window-demo.html` 左下角可以实时切这两个尺寸。
