# 窗口 chrome · 设计源

这一份是 HTerMinaL 窗口外观的**唯一设计源**。后续所有窗口相关的样式、结构、动效，都以这里的图形为准，
不再另起一版。

文件都源自手绘原稿（Inkscape，A4 画布），我按原稿的图形语言重画并修掉了其中的小毛病。
每个文件头部都写着「原稿是什么 / 保留了什么 / 改了什么」，改的时候请连注释一起维护。

| 文件 | 内容 |
| --- | --- |
| `window.svg` | 窗口主图，静止态，透明底，768×600 |
| `window-fullscreen.svg` | 全屏态，演示「缺口 → 毛玻璃」 |
| `red.svg` `yellow.svg` `green.svg` `blue.svg` | 四枚按钮，32×32，24×24 栅格上的字形可单独取用 |

> 这几张图是**深色墨线 + 玻璃质感**的设计，直接双击在白色背景的看图器里打开，提手和轮廓会几乎看不见。
> 请放在深色底（`#0b1018` 一类）上查看，或看仓库外的效果图。

## 一、这套 chrome 到底是什么

不是「一个带标题栏的盒子」，而是：

> **一块浮着的画面，顶上抬着一条提手，四枚色点抱在提手两侧。**

三条贯穿全部：

1. **标题零布局影响** —— 提手和色点都在画面【外面】或【上面】，画面永远是完整的一块。
   加不加标题、标题多长，画面尺寸一个像素都不变。
2. **提手宽度固定** —— 提手是「提手」，不是「标题栏」。标题塞不下就截断，绝不撑大提手。
3. **只有画面是实体** —— 除画面外全部透明：提手是玻璃，色点是实心，窗口外完全透出桌面。

## 二、几何

以 768×600 的画布为准，画面 720×460。

```
                        ┌──── 提手 312 宽、48 高 ────┐
        ●      ●       ╱                            ╲       ●      ●
       红     黄      ╱         hsl2 · FreeBSD 12.0  ╲      绿     蓝
                    ╱                                  ╲
       ┌───────────┴────────────────────────────────────┴───────────┐
       │                                                              │
       │   画面  720 × 460，圆角 20                                   │
       │                                                              │
       └──────────────────────────────────────────────────────────────┘
       └─ 距中心 ±228 ─┘└─ ±166 ─┘              └─ ±166 ─┘└─ ±228 ─┘
```

| 项 | 值 | 说明 |
| --- | --- | --- |
| 画面 | 720 × 460，圆角 20 | 唯一的实体，深色渐变 `#131820 → #0a0d12` |
| 提手 | 底边 312、顶边 200、高 48 | 梯形，顶角半径 ~14；与画面**同一条轮廓**，接缝处没有第二条线 |
| 色点 | ⌀14（r 7），`cy` = 提手带中点 | 距中心 ±228（外）/ ±166（内） |
| 标题 | 15px / 500，居中 | 基线压在提手下沿（`y=88`），光学高度与色点齐平 |
| 轮廓 | 1px `rgba(255,255,255,.13)` | 只勾外缘，不做厚边框 |
| 投影 | `0 18px 22px rgba(0,0,0,.55)` | 只往下拖一点 |

**为什么色点不在角上。** 原稿把四枚点放在「提手两肩」——内两枚正好贴住提手两只脚，外两枚再往外一格。
这不是随手摆的：它让 `[● ●][提手][● ●]` 成为**一整条居中的提手横杆**，窗角留白。
代价是窗口变窄时这条横杆会挤到边，所以落地时按下面收：

- 窗口宽 ≥ 420：横杆原样居中；
- 420 ～ 300：提手等比缩窄，色点向两侧让位；
- < 300：只剩提手和一个「⋯」入口，色点收进菜单。

## 三、四枚按钮

左组负责「离开」，右组负责「展开」——按语义分组，不是 macOS 的三键全在左。

| | 语义 | 图形 | 依据原稿的哪一笔 |
| --- | --- | --- | --- |
| 🔴 `#FF4A3D` | 退出程序 / 关闭窗口 | 三边框体（右侧开口）+ 一支向右逸出的箭 | 原稿「三段直边 + 右下方甩出的曲面」 |
| 🟡 `#FFCC00` | 最小化 | 下沉的箭 + 一条托盘线 | 原稿「横带 + 向下折回的曲面」，补上了落点 |
| 🟢 `#2FD158` | 最大化 | 两枚对角楔形，朝右上 / 左下撑开 | 原稿「双头缎带的双向扩张」 |
| 🔵 `#35C5F2` | 置于所有窗口最下面 | 一扇实窗 + 后面一扇更淡的 L 形窗 | 原稿「互相咬合的阶梯」，只画露出来的部分 |

几个共同约定：

- **字形永远是一个动作，不是一件物体**。红黄绿是「往哪儿动」，蓝是「z 序」，所以只有蓝没有箭头。
- **墨色统一 `rgba(0,0,0,.58)`**，不跟按钮同色。四枚里黄最亮，白墨在黄上等于没有；统一压深墨，
  四枚的分量才一致。（原稿的白色描边是「画在白纸上」的产物，落到深色 UI 上必须反转极性。）
- **静止时不显示字形**，`hover` / 聚焦时 0.13s 淡入。窗口宁静，指过去才露。
- 颜色取自原稿色相，只压低纯度：`#ff0000 → #FF4A3D`、`#00ff00 → #2FD158`、`#00ffff → #35C5F2`，
  黄沿用原稿 `yellow.svg` 的 `#ffcc00`。纯红纯绿纯青在深色玻璃上会「跳」，压一档才稳。

## 四、两条容易被做错的规则

### 1. 标题塞不下：中间截断，提手不许变宽

`hsl2 · FreeBSD 12.0-RELEASE r341666 · 第 1 层`
→ `hsl2 · FreeBSD 12.0…第 1 层`

保留**头**（身份）和**尾**（状态），砍中间。CSS 的 `text-overflow: ellipsis` 只能砍尾，
所以落地时要量宽：以**文字底线处提手的宽度**为准算可用宽度，逐字收窄到装得下为止。
（这一版 `window-fullscreen.svg` 一开始就是按视觉估的，字压到了斜边上，已按实测 205px / 余量 32px 收紧。）

### 2. 全屏：缺口变毛玻璃

窗口不是方的 —— 四个圆角和一条提手，普通态靠「透明」把它们藏掉。全屏时没有桌面可露，于是：

| 普通态 | 全屏态 |
| --- | --- |
| 提手抬在画面**外面** | 提手翻进画面，变成一个向下的梯形凹槽 |
| 四角圆角外露桌面 | 四角缺口（半径压到 14）填毛玻璃 |
| 缺口 = 透明 | 缺口 = 雾层 + 细颗粒 + 一道厚度高光 |

一句话：**普通态靠透明藏起来的地方，全屏时一律换成毛玻璃**。
落地时用 `backdrop-filter: blur() ` + 半透明白 + 一层噪点纹理即可，不必真的画图。

## 五、从原稿改掉的东西

按文件对照，方便回溯：

| 原稿的问题 | 怎么改的 |
| --- | --- |
| A4 画布 + 内容缩在角落（210×297mm 里画 160mm） | 全部改成紧贴内容的 viewBox，无多余留白 |
| 画面矩形与梯形提手是**两条独立路径**，底边叠出双线 | 合并成一条闭合轮廓，提手直接从画面顶边长出来 |
| 四枚点是**椭圆**且大小不一（rx/ry 5.03/4.71、5.49/4.97…），间距也不等 | 统一 ⌀14 正圆，间距 62/332/62，严格左右对称 |
| 色点位置按画面百分比摆放（约 20% / 27.5%） | 改成「距中心固定偏移」，窗口缩放时横杆不变形 |
| 标题是黑字白描边（画在白纸上的做法） | 改成浅色实字，靠提手的玻璃底承托 |
| 四枚字形是**色块 + 白描边**，缩到 14px 糊成一片 | 改为深墨字形，笔画收到 2 单位；绿色月牙改实心楔形，蓝色拉开前后间距并做「近实远虚」 |
| 提手玻璃在画面顶边处突然收住 | 渐变必须淡到 0，否则提手根部会横着裂一条线 |

## 六、落地要点（写给动手改代码的人）

- 画面 `inset: 0` 铺满窗口；提手与色点是 `position: absolute` 的兄弟节点，**不进文档流**。
- 提手那一带（高 48）除了色点和提手本身，其余 `pointer-events: none`，避免挡住画面顶部的内容。
- 拖动热区 = 提手整块 + 两肩空白（即顶部整条 48 高的带子），双击 = 最大化 / 还原。
- 四枚色点用 `<button>`，`aria-label` 写「关闭 / 最小化 / 最大化 / 置于底层」；
  蓝键要能连续按（每次再降一层），到底时置灰。
- 全屏态切换的是**同一套 DOM**：只加一个 `is-fullscreen` 类，改提手的方向、圆角半径、缺口的填充，
  不另起一套结构。
